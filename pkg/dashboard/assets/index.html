Documentation

From installation on Windows/WSL2 and Linux to running OCI containers & GUI monitoring

1. What is Containia?

Containia is an educational, production-patterned Mini Container Runtime built from scratch in Go. It does not rely on Docker daemon or runc — it orchestrates Linux kernel primitives directly:

Core Rule: A container is not a Virtual Machine (VM). It is simply an ordinary Linux process running with restricted view boundaries (Namespaces), resource limits (Cgroups v2), isolated layered filesystem (OverlayFS + pivot_root), and virtual routing (Linux Bridge + veth).

2. Installation & Setup Guide

1
Enter WSL2 Environment (Windows Users)

Because Linux namespaces and cgroups v2 require a Linux Kernel, on Windows open PowerShell or Windows Terminal and launch WSL:

wsl

Note: You do not need to specify flags if docker-desktop or Ubuntu is your default WSL distro.

2
Navigate to Project Directory in WSL

The project is placed in your WSL filesystem (or mounted from host):

cd /root/containia
3
Compile Binary (Optional if binary already present)

If you modify the Go source code, build the Linux binary:

go build -o containia ./cmd/containia
4
Launch Web Monitor GUI

Start this web dashboard server on port 8080:

./containia ui -p 8080

Then open your browser in Windows at http://localhost:8080

3. CLI Commands Reference

Action Command Description
Pull OCI Image ./containia pull alpine
./containia pull postgres:18		 Downloads multi-layer OCI images from Docker Hub (registry-1.docker.io) with auto token refresh.
Interactive Shell ./containia run -it alpine /bin/sh Launches container attached to terminal with PID 1 isolation and private hostname.
Run Background Container ./containia run -d --name my-app -m 256m --cpus 0.5 alpine sleep 3600 Runs container in detached mode with memory limit (256MB) and CPU limit (0.5 core).
Build Dockerfile ./containia build -t my-db:1.0 ./Project/db Parses FROM, ENV, WORKDIR, EXPOSE, CMD, ENTRYPOINT, COPY and builds layered image.
List Containers ./containia ps (or -a) Shows running containers, image names, commands, IP addresses, and uptime.
Container Logs ./containia logs <name-or-id> Streams stdout/stderr output from detached containers.
Execute in Container ./containia exec <name> ps aux Enters running container's namespaces via nsenter to run diagnostics.
Stop Container ./containia stop <name-or-id> Sends graceful SIGTERM followed by SIGKILL and cleans up bridge veth.
Remove Container ./containia rm <name-or-id> Safely unmounts OverlayFS layers and cleans up /var/lib/containia state.
Remove Image (RMI) ./containia rmi <image-name> Deletes image descriptor and garbage-collects unreferenced layers.

4. How to Use the Web Dashboard

🚀 Launching Containers via GUI
Click the "New Container" button at top right. Select an image from local quick-picks, set memory boundaries (e.g. 256m), customize ENV variables, and click Launch.
📋 Real-time Logs Terminal
On any container row, click "Logs" to open the live terminal viewer. The log window polls output automatically every 2 seconds.
💿 Pulling Images from Docker Hub
Click "Pull Image" at top right. Choose popular images like alpine, postgres:18, node:20-alpine or type any public Docker Hub reference. Progress streams live.
🏗️ Building from Dockerfile
Switch to the "Dockerfile Builder" tab. You can inspect or modify instructions (like the Project/db Dockerfile) and click "Build Image" to view real-time build output.
🌐 Virtual Network Inspector
Switch to the "Kernel & Network" tab to see the Linux Bridge containia0, subnet routing, veth interfaces, and NAT MASQUERADE rules.
⚡ Real-time Cgroups v2 Meters
The Memory bar in the Containers table dynamically reads /sys/fs/cgroup/containia/<id>/memory.current directly from the Linux Kernel to show actual RAM usage.

5. Troubleshooting & FAQ

Q: Why does running ./containia directly in PowerShell fail?
A: containia is an ELF Linux executable. Linux Namespaces, Cgroups v2, and OverlayFS are core Linux Kernel features. On Windows, always run via WSL by typing wsl first.
Q: Can I access http://localhost:8080 from Windows?
A: Yes! WSL2 automatically mirrors ports bound on 0.0.0.0 to Windows localhost, allowing you to view the dashboard in Chrome, Edge, or Firefox seamlessly.
Q: How does Containia prevent duplicate layer downloads?
A: Containia uses Content-Addressable Storage in /var/lib/containia/layers/<sha256>. If two images share base layers, Containia identifies the SHA256 digest and reuses cached layers instantly.

💥

Fork-Bomb Defense

Cgroups v2 pids.max

Spawns 200 concurrent background processes inside the container. Demonstrates that Linux kernel refuses new forks with EAGAIN: Resource temporarily unavailable when hitting pids.max, completely protecting host OS stability.

🛑

Kernel OOM Killer

Cgroups v2 memory.events

Allocates memory exceeding memory.max boundary. Watches the Linux Kernel invoke Out-Of-Memory (OOM) Killer to terminate the offending thread, incrementing the kernel oom_kill hardware event counter.

⚡

CFS CPU Quota Throttling

Cgroups v2 cpu.stat

Launches a heavy arithmetic computational loop. Observes Linux Completely Fair Scheduler (CFS) actively freezing execution slices and recording throttled_usec in cpu.stat according to the assigned quota.

Copy-on-Write (CoW) Inode

OverlayFS Union Mount
